# 森友小镇开张日

Blender 原创微缩场景 + Three.js 交互体验，静态部署在 GitHub Pages。

## 9 月 24 日会议后的新版：蚂上懂我

独立入口：[meet.html](https://santisino.github.io/senyou-town/meet.html)。旧版首页、活动流程、存储键和三维资产保持不变。

本轮只把「一个人的完整呈现」和「一次认识另一个人的过程」做完整，不把整套长期平台的设想都变成已实现功能。

推荐演示顺序：

1. 用模拟报告开始 → 勾选本次演示同意 → 生成小禾的介绍；也可跳过报告，手动填写。
2. 修改自己的标签、协作提示、兴趣、经历、近期探索、找人事项及状态；可选小屋颜色、发型和衣服。
3. 看「门前认识 → 会客桌 → 档案袋」，再切换访客视角。日常、协作提示可分别隐藏；深层档案可拒绝申请。
4. 打开「认识森友」，按不同组、找人中、组局或学习筛选，也可搜索名字、公开兴趣、特点和事项。五位虚构森友包含未填完整、已成局与不开放档案的状态。
5. 找到小林，去小屋看公开介绍与会客桌，发现共同话题；申请深层档案，在明确标记的演示控制中选择同意或拒绝。
6. 双人合拍需另行演示双方同意；展示的是人工编写的协作小约定，不是专业合拍结果。撤销个人档案授权也会收起合拍样例。
7. 准备、修改、保存或复制一句招呼；本机保存不等于已经发送，现实联系渠道仅作提示。

新版文件：`meet.html`、`meet.css`、`meet-app.js`（状态与交互）、`meet-data.js`（虚构样例及纯逻辑）、`meet-views.js`（分层呈现）。复用 `opening-world.js` 的 Blender 场景，未重新构造代码几何替代三维资产。

边界：全为虚构人物与人工编写的报告转译示意。无真实测评、员工报告、专业合拍分数、企业登录、钉钉发送或多人同步。权限在前端本机模拟，不具有正式系统的安全隔离能力。新版仅写入 `senyou-meet-demo-v1`，不读写旧个人档案与活动数据。

本轮本地验证：26 项纯逻辑检查通过；应用内浏览器走通生成、编辑、隐私预览、搜索、授权同意／拒绝／撤销、合拍独立同意、草稿保存与复制、无报告手动填写、刷新持久化及取消编辑。检查 1440×1000 与 390×844 视口，手机内容宽度 390 像素，无横向溢出。未把本机单人演示当作企业现场或真实多人验收。

## 怎么体验

- 给合作伙伴演示：点「先逛一逛小镇」，不填资料即可看示例木牌、档案袋、会客桌与共建说明。示例不写入个人档案或活动记录。
- 演示现场培训方式：点「看看培训现场怎么玩」，查看组织者创建活动、学员扫码入住、串门共建和带走成果的流程，并可预览学员扫码后的页面；此预览不连接活动。
- 自己体验完整流程：导览最后点「布置我的小屋」，完成形象和 24 道问答，再确认自己的档案。已有个人档案时显示「继续我的个人体验」，不再称为「继续我的小镇」。
- 正式培训：组织者从首页角落的「组织一场活动」创建并命名活动，直接进入主持台，无需先完成个人问答。点「展示学员入住二维码」投屏，或复制学员邀请链接。
- 学员扫描二维码或打开活动邀请链接，直接看到本场欢迎页；确认参与后进入形象和档案准备，无需选角色或重填邀请码。没有二维码时，也可手动输入 16 位邀请码。
- 主持人依次开放「串门」「共建」「开张」。参加者只能修改自己的资料，不能控制阶段。
- 共建项目先保存讨论稿，由另一位实际成员确认，再共同提交。修改稿件会使旧确认失效。
- 可以在门牌认识彼此，在档案袋了解习惯，在会客桌讨论合作，在信箱留下消息和约定。
- 档案袋先展示一句话和一段短介绍，会客桌先展示三张便签；详细自述按需展开。归纳基于本地文字模板，须本人确认后分享，不调用外部 AI。
- 同一对伙伴首次确认合作或支持，各获得 4 份协作能量；共同项目交付后，每位成员获得 10 份。先收取能量，再主动浇水；串门、浏览和重复点击不加分。
- 合种广场从树苗随浇灌逐步生长，带有能量球、浇水壶、合种木牌及梭梭、胡杨、花棒微缩展示。主持人可以给本场合种林命名。
- 至少一个项目交付且有人浇水后可以开张，修订说明书、记录发现，并下载居民卡和带参与者署名的本场合种纪念。
- 旧档案不覆盖原始自述，新短介绍需要本人确认；旧场次已确认合作与交付可补领一次能量。

## 实时场次的边界

多人场次采用 PeerJS 1.5.5 信令和 WebRTC 数据连接，主持人浏览器是场次中枢。**主持人必须保持页面和网络在线**；这不是全天候云端服务。现场企业网络可能限制 WebRTC，请正式培训前用实际设备试连。代码设置 60 人上限，但不意味着已经完成 60 人并发实测。

场次存于主持人本机，可用「恢复上次主持的场次」恢复。参加者离线时，主持人可保管消息；参加者使用同一浏览器重连原场次后可看到。清理站点数据会清除本地身份和资料。多台设备之间不自动迁移身份。

每 12 间小屋组成一个可切换的街区。公共项目进展默认折叠，不把浏览次数或能量当成人格、能力或受欢迎程度的排名。

## 内容与隐私

题目参考 DISC 报告的沟通、行为偏好、信息需求、角色协作、困难应对等主题，属于原创自我探索题，**不是供应商 DISC 原题或经验证量表**。结果是本人确认的自述，不输出专业类型、能力分、心理健康诊断或合拍百分比。

原始答题只保存于本人浏览器。只同步本人确认分享的档案；支持需求默认不分享。未开放街区前，不向其他参加者同步个人档案正文。留言和合作约定只向双方呈现，但主持人作为数据中枢可以接触场次数据。请使用昵称，不填机密、联系方式和不愿分享的内容。项目方案和参与名单属于本场公开内容。

未将原报告、真实姓名、电话或报告链接放入项目。蚂蚁森林的合种、树友、梭梭/胡杨、物种观察等只作为文化与场景启发。游戏能量不等同于真实绿色能量、碳减排或公益捐种；本体验不代表蚂蚁森林官方产品。

## 运行与文件

使用任意静态服务器，例如 `python3 -m http.server 8777`，打开本地地址。无需构建。

- `opening-content.js`：题目、报告主题映射、说明书和公共项目内容。
- `opening-entry.js`：无填写导览、培训流程与学员视角预览、邀请解析和本地二维码生成。
- `opening-session.js`：主持端校验、阶段、私信、共同确认、实时同步。
- `opening-energy.js`：一次性奖励、个人收取和公共浇灌账本、旧场次迁移。
- `opening-story.js` / `opening-cards.js`：短介绍归纳、本人确认、档案与便签分层展示。
- `opening-world.js`：场景、相机、形象与房屋点缀、街区和设施显现。
- `opening-app.js` / `opening.css`：界面、流程和居民卡导出。
- `assets/opening-day.glb`：Blender 导出的新场景。
- `assets/resident-v2.glb`：Blender 角色模型。
- `source/build_opening_day.py`：可复现的小镇建模、GLB 压缩导出和预览渲染脚本；通过 `blender --background --python source/build_opening_day.py` 运行，源场景和预览保存在 `build/opening-day/`。
- `vendor/PEERJS-LICENSE.txt`：PeerJS MIT 许可。
- `vendor/qrcode.mjs` / `vendor/QRCODE-LICENSE.txt`：qrcode-generator 2.0.4 与 MIT 许可；二维码在本机生成，不调用外部二维码服务。

无 API 密钥、付费接口和第三方分析埋点。
