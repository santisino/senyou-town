# 蚂蚁森友会 Forest Demo

独立路由 `/forest/`，旧版页面与存储不变。Blender 是场景几何源；Three.js 负责显示、移动与点选；原生 DOM 负责可读内容。

## 已锁定设计

- 暖木 D7AF78 / 奶油纸 F9EED7 / 苔绿 57814C / 陶土 C78160；开放式全屏世界，轻量纸感面板。
- 首页不自动弹窗，也没有预建的个人小屋。玩家先在村口走近村长、报上称呼、领取宅地，再过桥走到工具箱搭建基础小屋。点击远处目标会寻路走过去，不远程打开面板。
- 个人表达分布在门牌、兴趣角、会客桌、心愿瓶四处物件。每处保存后回到房间；最后走到物理册子旁确认。不再存在连续四页填写入口或手机远程物件栏。
- 森友公告栏承接居民列表；选择拜访后沿路行走。信箱、送礼和公共活动均需走近对应地点触发。键盘或摇杆可中途接管寻路。
- 地图找人 → 小屋逐层认识 → 物理册子连贯阅读。同一 `Resident` 资料源，访客统一经过投影。
- 真实本地功能：填写、编辑、走动、筛选、库存、申请、公共活动结果和刷新保存。
- 显式模拟：其他居民、跨角色响应、DISC 建议、合拍建议、线下活动完成；不包含真实登录、后台权限或跨设备同步。
- 核心完整度由本人确认而非隐私披露量衡量。隐藏资料不减少装饰资格。

## 邻居来访与情境表达（neighbors-v1）

- 修复从门前立即进屋后当前主人被清空的顺序错误；无法寻路时给出明确提示。屋内无公开资料也会明确说明，不静默无响应。
- 完成个人说明书并开放串门后，退出面板探索约 8 秒，会收到一次明确标注为本机模拟的森友来访礼物。信箱立起小旗，屋内出现礼物，导航提示回家；不自动弹窗。演示者也可手动触发。每个角色一次，复点或刷新不重复赠送，使用示例发送者原有库存与限额；收下不自动成为好友。没有已准备好的可送礼示例居民时不虚构发送。
- 兴趣角提供 3 道主问＋3 道可选追问；会客桌提供 4 道主问＋3 道可选追问。建议选项可自由改写，回答逐字本地保存，原始回答私密。只按回答整理文字，不推断人格；本人预览修改、选择公开范围并确认后，才更新共享的个人资料。原来的直接编辑入口保留在可展开区域。
- 公共空间提供用途、三步操作与折叠的 Demo / 正式产品边界说明。图书馆收藏笔记后可拜访分享者；成长林先领观察任务，反思保持私密，只有本人确认才修改介绍。
- 游乐场是协作体验场：可与现场伙伴面对面商量，共用设备记录；也可选择预设回应的模拟搭档。共同花园有植物数量和中间通道约束，现场模式须本人确认已共同讨论才完成。改变布局后需要重新确认，无人格评分或真实多人同步。
- 工坊围绕森林拍照地图共创。地图包含两条明确标注的预置贡献，用户可选地点、补充观察，生成署名标记与分享卡。草稿刷新可恢复；不是实时多人共编。
- `interview.js` 管理情境问题与基于原话的整理，`space-guides.js` 管理空间指引、拍照地点和花园约束。新增小旗是网页运行时几何，木屋等主要资产仍复用 Blender 模型。

## 共同建村（village-v4）

- 溪流西侧是五条居民街巷，每巷十个唯一宅地，共 50 个地址；东侧集中公园、图书馆、成长林、游乐场、教室、工坊、小铺，三座桥连接两区。
- 房屋生命周期：未分配宅地 → 领取钥匙/出现工具箱 → 搭建木架 → 布置中的小屋 → 本人确认说明书/挂欢迎牌。领取钥匙不自动造好房屋。装修与公开多少个人资料无关。
- 默认只有自己到达，没有小林等人的成品房。虚构同学随报到、建房和表达里程碑逐步安家；场景中的少量行走邻居也是模拟，不是真实在线用户。
- 村庄开放与个人准备好是两个状态。开放不代替未完成者确认资料；晚到的人仍可报到建设。已完成者可以去小铺、制作礼物或探索公共道路，不必等待弹窗。
- 未确认的邻居资料和筹备阶段的邻居介绍都不对访客展示；名册、门牌、小屋、册子读取同一份资料。
- 演示者有两个明确起点：「从空宅地重新体验」（二次确认后重置当前新版数据）与「进入已建村庄演示」（准备虚构样本，不填写自己的资料）。另可装入 50 人样例，通过「模拟下一批同学安家」推进；不会出现重复地址或多人共用一间展示屋。
- `layout.js` 是寻路/地址布局；Blender 导出清单与布局由自动测试逐项比对。`settlement.js` 是建设状态与虚构同学进度规则。

## 森林明信片（postcards-v1）

五种卡均输出 1080×1440 PNG，复用 Blender 真实资产与已确认的资料；不是概念图。入口只在主动走近物件后出现，不在入驻或互动完成时自动弹窗。

| 卡片 | 入口 |
| --- | --- |
| 小屋明信片 | 确认个人说明书后，屋内「留影相机」 |
| 森林个人名片 | 自己的《小屋里的我》→ 做我的森林名片；留影相机也可进入 |
| 心愿邀请卡 | 自己的心愿瓶 → 做一张心愿邀请卡（需要公开有效心愿） |
| 双人同行卡 | 会客桌 → 制作同行明信片（需要已接受的心愿申请或森友连接） |
| 共创成果卡 | 工坊保存贡献后 → 制作共创成果卡 |

生成预览前可以取消公开字段、写附言、选拍摄角度；修改后旧图与确认状态立即失效。下载不会修改个人说明书。长文按版式截取并显示省略号，不编造摘要；以导出前的预览为准。

双人卡先由一方发起，同一版内容在对方信箱中等待确认。演示者切换另一位虚构角色，走到信箱查看并同意后，双方才可下载无水印的正式卡。单方面已连接不等于授权公开。资料、公开范围或连接变化后旧卡不再提供下载；已经保存出去的图片不能远程收回。共创卡记录本人实际提交的贡献，搭档贡献明确标为示例，不宣称线下活动已经完成。

`share-data.js` 限制可分享字段并管理双人确认；`share-render.js` 在独立场景中拍摄模型、Canvas 排版、生成图片及二维码；`share-ui.js` 管理预览、下载、系统分享及异常反馈。模型与材质复用现有 Blender 工程，不需要每次导出时启动 Blender，也不会改变玩家镜头与位置。

手机通过能力检测调用系统文件分享，不支持时提供图片预览、长按提示和 PNG 下载。系统分享目标与保存位置依赖浏览器，不能保证自动保存到相册或直接发布朋友圈。二维码始终标注为通用 Demo 入口，不携带个人数据，不能跨设备直达本机私人小屋。双人请求仍是本地模拟，无后台发送。

## 自由镜头操作

- 电脑：左键按住拖动，水平不限角度旋转并调整俯仰；滚轮/触控板滚动缩放；右键或 Shift + 左键拖动平移。
- 手机：单指拖动旋转；双指张开/合拢缩放，两指一起移动平移。左下角摇杆仍负责走路，轻点地面或物件仍负责游戏互动。
- 森林镜头距离 3.2–500，小屋 2.5–65。俯瞰森林按屏幕长宽比容纳整个村庄；远景空宅地收为小方点，建设中为暖棕标记，拉近或悬停可看名称。
- 普通旋转/缩放不会破坏人物跟随；平移后进入自由观察。右上角「镜头复位」回到当前场景的舒适视角，森林中恢复跟随人物。
- 俯仰保留地面保护，不允许镜头翻到地下。只有单指/鼠标短点按触发场景操作，拖动、多指手势和右键不会误触发走路、进屋或对话。

## 源与构建

`source/build_forest.py` 使用旧版构建器的几何函数生成新资产，不运行旧版导出流程。命令：

```
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python forest/source/build_forest.py
python3 -m http.server 8777
node --test forest/tests/state.test.mjs
```

交付的 Blender 工程在 `forest/source/forest.blend`，网页模型在 `forest/assets/forest.glb`。构建脚本复用 `source/build_opening_day.py` 的几何函数，因此请保留目录层级，不要只复制单个 Python 文件。重新构建时，工程直接写入 `forest/source/forest.blend`，模型写入 `forest/assets/`；不会改写旧版根目录页面的模型。

打开本地服务后访问 `http://127.0.0.1:8777/forest/`，不要直接双击 HTML 文件。需要现代浏览器的 WebGL、ES Modules、CompressionStream 支持。Blender 仅在重新制作模型时需要，普通网站体验不依赖 Blender 安装。

上线地址：https://santisino.github.io/senyou-town/forest/

此前的使用说明：https://ezvy2mkvjo.feishu.cn/docx/D8p2dfpwYoanDrxiDIOcuGNPngf （该文档尚未同步本次共同建村变更；当前操作以本 README 和网站为准。）

## 本地数据接口

`data.js`：示例居民及公共空间；`state.js`：统一资料/展示投影、入驻进度、经济及社交事务；`journey.js`：物件任务与避障寻路；`camera.js`：自由镜头与点击/拖动手势分流，使用已有的 Three.js OrbitControls；`world.js`：Blender GLB 加载、场景、移动、近距离交互与遮挡处理；`app.js`：界面与演示编排。

`config.js` 只压缩公开村庄设置以生成扫码链接，不包含任何居民资料、礼物、申请或本地状态。不同设备各自体验，不互相同步。

当前存储键 `senyou-forest-village-v2`。旧 `senyou-forest-demo-v1` 保留不动，新村不继承旧版已建好的样例。身份切换只用于本地模拟，不能作为生产权限实现。隐私选项只控制演示展示，不构成浏览器本地数据安全隔离。

## 验收路径

无弹窗进入森林/空宅地 → 找村长报到领位置 → 过桥到宅地打开工具箱 → 搭建后回到世界看变化 → 进屋在四处物件表达 → 确认册子挂欢迎牌 → 主持人开放（未完成邻居仍在布置）→ 走到公园公告栏找人 → 沿路拜访对应地址 → 心愿申请与信箱回应 → 刷新恢复。

演示者手册中的「章节跳转」是明确的讲解快捷方式，不是普通玩家入口；除此之外，打开演示者手册不会赋予玩家隔空交互能力。

2026-09-28 的游戏交互修订验收记录与真实截图位于工作区 `output/森友会-新版交付/gameplay-local/` 与 `gameplay-online/`；旧版 PDF、截图及 30 分钟测试属于旧版本证据，不应当作本次交互修订的验证结果。

阶段记录、实际截图、独立 Chrome 自动操作脚本、PDF 与验收结果保存在工作区 `output/森友会-新版交付/`。代码规则测试使用 Node.js，无额外 npm 安装步骤。浏览器验收脚本是交付证据而非生产依赖；其中的 Playwright 绝对路径需按执行机器调整。

## 模型语义接口

GLB 根节点为 `Village`、`Home`、`Avatar`、`Templates`。Templates 包含空宅地 PlotGround、工具木料 Construction、木架 HouseFrame、外观 Cabin_00、欢迎花圃 WelcomeGarden；网页实例化成 50 个唯一地块并按状态切换，原始模板在网页隐藏。小屋内容节点：`Doorplate`、`Camera`、`Table`、`Book`、`Wish`、`Mailbox`。装饰节点：`PlantDecor`、`FlowerDecor`、`GiftDecor`、`Rug`。人物节点使用 `Avatar_Head/Torso/ArmL/ArmR/LegL/LegR`，网页驱动肢体行走，不把文字烘焙进模型。

替换美术时保留这些稳定名称与局部坐标；需要修改场景尺寸时，同时核对 `world.js` 的物件交互位置与碰撞边界。`forest/assets/manifest.json` 列出当前分组。

## 演示数据与安全边界

- `me` 是当前浏览器自己的填写；小林、小禾、阿泽等为虚构数据。
- 普通体验只能在本人确认且村庄开放后拜访其他居民。演示者入口能切换虚构角色，这不是服务器权限。
- 每人 100 森友币、5 件招牌礼物；每场最多送 5 次；装饰 10/20/30 币，商店礼物 20 币，收到并接受后可回收 8 币。
- 只改装饰不影响完成状态；报告示例须授权，且不覆盖本人已经填写的文字。
- 重置前会二次确认，仅替换新版独立存储键。清除浏览器网站数据也会丢失本地记录。
- 50 人班级容量是独立地块、状态和列表的本机演示，不是 50 个在线用户；演示者可切换包括迟到者在内的各个示例居民。规则测试另保留 100 条列表数据搜索用例，不将其当作村庄容量或实时并发测试。
- QR、分享文案和运行画面不应使用真实员工敏感资料；专业测评不在本地 Demo 中解析。
